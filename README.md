# WoolyNpcs

NPC плагин для **Paper 1.21+** с интеграцией **ModelEngine R4.0.9**.

## Особенности

- **ModelEngine модели** — каждый NPC использует кастомную модель из ModelEngine
- **Система действий** — 31 тип, включая составные RANDOM и SEQUENCE, флаги игрока FLAG_SET/FLAG_CLEAR, действия над самим NPC (NPC_ANIMATION, NPC_LOOK, NPC_WALK_TO, NPC_HOLOGRAM_SET) и свои типы через API
- **Система диалогов** — в чате или окном инвентаря; условия и действия на вариантах, автопереход, звук узла, печатная машинка, возврат назад, переменные `{flag_...}`
- **Маршруты (Waypoints)** — точки со скоростью и анимациями, привязка к земле и обход препятствий, показ маршрута частицами
- **Режимы перемещения** — follow (идти к игроку) и wander (бродить вокруг дома)
- **Распорядок дня** — NPC уходит к прилавку утром и домой вечером по времени мира
- **Расписание** — NPC появляются/исчезают по времени мира (day/night cycle)
- **Триггеры событий** — ON_ENTER, ON_LEAVE, ON_JOIN, ON_KILL, ON_DEATH_NEARBY, ON_TIME
- **Голограммы** — TextDisplay с PlaceholderAPI, настраиваемый стиль
- **Слежение за игроком** — NPC поворачивается к ближайшему игроку
- **Условия действий** — [PERM:], [ITEM:], [GAMEMODE:], [REGION:], [REALTIME:], [WEEKDAY:], [CHANCE:], [FIRSTJOIN], [FLAG:], [CD:], [ONCE], [DELAY:], [MONEY:], [EXP:], [WORLD:], [TIME:], [WEATHER:] и универсальное [PAPI:]; поддерживаются отрицание и группы OR/AND
- **Награда за клики** — автоматическое награждение каждые N кликов
- **Экспорт/Импорт** — перенос NPC между серверами через YAML-файлы
- **Данные игроков** — кулдауны, [ONCE], флаги квестов, скрытые NPC и личная статистика; YAML, SQLite или MySQL
- **Права доступа** — ограничение взаимодействия по permission, точечные права на подкоманды и отдельных NPC
- **GUI редактор** — модель и анимация списком, действия, маршрут, режим движения, подтверждение удаления
- **Меню** — настраиваемые интерфейсы в папке `menus/`, открываются действием OPEN_GUI
- **Vault + PlaceholderAPI** — опциональная интеграция; плагин и сам предоставляет плейсхолдеры %woolynpcs_...%
- **API для разработчиков** — события NPC и диалогов, реестр пользовательских типов действий

## Зависимости

- **Paper 1.21+** (обязательно)
- **ModelEngine R4.0.9+** (обязательно)
- **Vault** (опционально — для [MONEY:], MONEY_GIVE и MONEY_TAKE)
- **WorldGuard** (опционально — для условия [REGION:])
- **PlaceholderAPI** (опционально — для плейсхолдеров в голограммах)

## Права

| Право | Что даёт |
|-------|----------|
| `woolynpcs.admin` | Все команды и все NPC (по умолчанию: op) |
| `woolynpcs.command.<подкоманда>` | Одну подкоманду, например `woolynpcs.command.list` |
| `woolynpcs.npc.<имя>` | Право править конкретного NPC |
| `woolynpcs.npc.*` | Право править любого NPC |

Точечные права позволяют выдать помощнику доступ к части NPC, не открывая ему
весь плагин. Подсказки по Tab учитывают права: команды, которых нет, не
предлагаются.

Обычным игрокам права не нужны: взаимодействие с NPC и выбор вариантов в диалогах
(служебная подкоманда `dialogchoice`, вызывается кликом по варианту ответа)
работают без `woolynpcs.admin`. Ограничить доступ к конкретному NPC можно через
`/wnpc permission <имя> set <право>`.

## Выбор NPC вместо ввода имени

Посмотрите на NPC и выполните `/wnpc select` — дальше в любой команде вместо
имени можно писать `@`:

```
/wnpc select
/wnpc holo @ line add &#A8E6CFПривет!
/wnpc anim @ wave
/wnpc lookat @ enable true
```

Если выбора нет, `@` берёт того NPC, на кого вы смотрите прямо сейчас.
`/wnpc select <имя>` выбирает по имени, `/wnpc select clear` сбрасывает выбор.

Подсказки по Tab для `/wnpc model` и `/wnpc anim` берутся напрямую из
ModelEngine — список моделей и анимаций конкретной модели.

## Действия над самим NPC

| Тип | Значение | Что делает |
|-----|----------|------------|
| `NPC_ANIMATION` | `<анимация> [секунды]` | Проигрывает анимацию; через N секунд возвращает основную |
| `NPC_LOOK` | `player [секунды]` или `reset` | Разворачивает NPC к игроку и удерживает поворот |
| `NPC_WALK_TO` | `<x> <y> <z> [скорость]` | Разовый поход к точке; маршрут на это время приостановлен |
| `NPC_HOLOGRAM_SET` | `строка1\|строка2` или `none` | Заменяет текст голограммы |

```
/wnpc action @ add RIGHT_CLICK NPC_ANIMATION wave 3
/wnpc action @ add RIGHT_CLICK NPC_LOOK player 5
```

## Действия над игроком

Помимо базовых `MESSAGE`, `PLAYER_COMMAND`, `SOUND`, `TITLE` и прочих:

| Тип | Значение | Что делает |
|-----|----------|------------|
| `BROADCAST` | текст | Сообщение всем на сервере |
| `MONEY_GIVE` / `MONEY_TAKE` | сумма | Выдать / снять через Vault |
| `ITEM_TAKE` | `<материал> [кол-во]` | Забрать предметы (только целиком) |
| `HEAL` | пусто или число | Восстановить здоровье |
| `FEED` | пусто или число | Восстановить сытость |
| `XP_GIVE` | `<кол-во> [levels]` | Выдать опыт или уровни |
| `OPEN_GUI` | id меню | Открыть меню из `menus/` |
| `CLOSE_INVENTORY` | любое | Закрыть открытый интерфейс |
| `DISCORD_WEBHOOK` | `<url> <текст>` | Отправить в Discord (асинхронно) |
| `RANDOM` | `ТИП:знач\|ТИП:знач` | Выполнить одно случайное |
| `SEQUENCE` | `ТИП:знач\|WAIT:20\|ТИП:знач` | Выполнить по очереди с паузами в тиках |

```
/wnpc action @ add RIGHT_CLICK RANDOM MESSAGE:Привет!|MESSAGE:Здорово!|SOUND:UI_BUTTON_CLICK
/wnpc action @ add RIGHT_CLICK SEQUENCE MESSAGE:Три|WAIT:20|MESSAGE:Два|WAIT:20|MESSAGE:Один
```

`RANDOM` и `SEQUENCE` разбирают подзадачи один раз при загрузке, поэтому флаги
`[CD:]` и `[ONCE:]` внутри них работают и сохраняют состояние.

## Меню (`menus/`)

`OPEN_GUI <id>` открывает меню, описанное в `menus/<id>.yml`. Кнопки используют
те же действия и условия, что и клики по NPC — магазин собирается без кода:

```yaml
title: "&#BBDEFBМагазин"
size: 27
items:
  '13':
    material: GOLD_INGOT
    name: "&#A8E6CFНабор за 100"
    lore: ["&#9CA3AFНужно 100 монет"]
    close-on-click: true
    actions:
      - "MONEY_TAKE:100"
      - "PLAYER_COMMAND:kit starter"
```

Управление: `/wnpc menu list`, `/wnpc menu reload`, `/wnpc menu open <id>`.
Пример создаётся автоматически при первом запуске.

## Условия действий

Все условия пишутся в квадратных скобках перед значением и складываются по И.

| Условие | Пример | Проверяет |
|---------|--------|-----------|
| `[PERM:]` | `[PERM:vip]` | Право у игрока |
| `[ITEM:]` | `[ITEM:DIAMOND:5]` | Есть 5 алмазов в инвентаре |
| `[GAMEMODE:]` | `[GAMEMODE:SURVIVAL]` | Режим игры |
| `[REGION:]` | `[REGION:spawn]` | Внутри региона WorldGuard |
| `[REALTIME:]` | `[REALTIME:09:00-18:00]` | Реальное время сервера (можно через полночь) |
| `[WEEKDAY:]` | `[WEEKDAY:SAT,SUN]` | День недели (`MON`…`SUN` или `ПН`…`ВС`) |
| `[CHANCE:]` | `[CHANCE:15]` | Срабатывает в 15% случаев |
| `[FLAG:]` | `[FLAG:stage=2]` | Флаг игрока установлен (и равен значению) |
| `[FIRSTJOIN]` | `[FIRSTJOIN]` | Игрок на сервере впервые |
| `[WORLD:]` `[TIME:]` `[WEATHER:]` | | Мир, день/ночь, погода |
| `[PAPI:]` | см. ниже | Сравнение через PlaceholderAPI |

**Отрицание** — восклицательный знак перед тегом: `[!PERM:vip]`, `[!REGION:spawn]`.

**Группировка** — `[OR:...]` и `[AND:...]`, части разделяются `|`
(внутри группы условия пишутся без скобок):

```
[OR:PERM:vip|PERM:admin]                 — достаточно любого из прав
[AND:ITEM:DIAMOND:1|!REGION:spawn]       — и алмаз, и не на спавне
[!OR:GAMEMODE:CREATIVE|GAMEMODE:SPECTATOR]
```

`[REGION:]` требует установленного WorldGuard; без него условие не выполняется
никогда. Подключение проверяется при первом использовании и пишется в лог.

## Условие `[PAPI:]`

Универсальная проверка через PlaceholderAPI — заменяет собой частные флаги и
связывает NPC с любым плагином, у которого есть PAPI-расширение:

```
/wnpc action @ add RIGHT_CLICK MESSAGE [PAPI:%player_level%>=10]Добро пожаловать!
/wnpc action @ add RIGHT_CLICK MESSAGE [PAPI:%vault_eco_balance%>=500]Богач!
```

Операторы: `>=` `<=` `>` `<` `==` `!=` и `~=` (содержит подстроку).
Если обе стороны — числа, сравнение числовое, иначе строковое.
Условий `[PAPI:]` в одном действии может быть несколько — выполниться должны все.

## API для разработчиков

События (все в `ru.qweyns.woolynpcs.api`): `NpcSpawnEvent`, `NpcDespawnEvent`,
`NpcInteractEvent` (отменяемое), `DialogStartEvent` и `DialogNodeEvent`
(тоже отменяемые).

Свои типы действий регистрируются в `onEnable()` вашего плагина:

```java
WoolyNpcsApi.registerAction("MY_SHOP", (player, npc, value) -> openShop(player, value));
```

После этого тип доступен в командах и файлах диалогов наравне со встроенными:
`/wnpc action @ add RIGHT_CLICK MY_SHOP оружие`.

## Редактор и управление

`/wnpc edit @` открывает редактор. Помимо прежних кнопок в нём теперь есть выбор
**модели** и **анимации** списком (данные берутся из ModelEngine, страницы
листаются), просмотр **действий** с удалением по клику, переключение **режима
перемещения** и переход к **маршруту** и **диалогу**. Удаление NPC и действия
спрашивают подтверждение — раньше одного случайного клика хватало, чтобы
потерять NPC со всеми настройками.

Удалённый NPC не пропадает сразу: он лежит в корзине и возвращается командой
`/wnpc undo`. Срок хранения — `settings.undo-minutes` (по умолчанию 10 минут,
0 отключает корзину).

`/wnpc list` показывает NPC постранично, с миром и координатами; клик по строке
телепортирует. Можно отфильтровать по миру: `/wnpc list 1 world_nether`.
`/wnpc near 30` покажет ближайших, `/wnpc search торг` — найдёт по имени или
модели.

## Поведение NPC

### Маршруты и рельеф

```
/wnpc waypoint @ add [ожидание] [анимация]   # точка на вашей позиции
/wnpc waypoint @ gravity true                # прижимать к земле
/wnpc waypoint @ show                        # показать маршрут частицами
```

**`gravity` по умолчанию выключена.** С ней NPC прижимается к земле, поднимается
на ступеньку и обходит препятствие, скользя вдоль стены. Без неё он идёт строго
по прямой между точками — как раньше. Выключено по умолчанию намеренно: прежние
маршруты рассчитаны на прямую линию, а для летающих моделей это единственно
верное поведение.

`show` рисует линию маршрута частицами лично вам. Повторная команда выключает
показ, сам он гаснет через две минуты.

### Режимы перемещения

```
/wnpc move @ follow 12        # идти к ближайшему игроку в радиусе 12
/wnpc move @ wander 8 0.1     # бродить вокруг дома, радиус 8, скорость 0.1
/wnpc move @ none             # выключить
```

`follow` держит дистанцию в два блока и возвращается домой, когда рядом никого.
`wander` делает перебежки с паузами. Оба режима важнее маршрута: пока они
включены, точки маршрута игнорируются.

### Распорядок дня

Расписание умеет только спаунить и деспаунить NPC. Распорядок добавляет то, ради
чего его обычно и хотят — «утром у прилавка, ночью дома»:

```
/wnpc routine @ add 1000 WALK          # в 1000 тиков идти на вашу позицию
/wnpc routine @ add 13000 WALK         # встаньте в другом месте и повторите
/wnpc routine @ add 13000 ANIMATION sleep
/wnpc routine @ add 23000 DESPAWN
/wnpc routine @ list
```

Типы: `WALK`, `TELEPORT`, `ANIMATION`, `SPAWN`, `DESPAWN`. Для `WALK` и
`TELEPORT` координаты можно не писать — возьмётся ваша текущая позиция.
Время задаётся в тиках мира (0 — рассвет, 6000 — полдень, 13000 — закат,
18000 — полночь).

### Триггеры событий

Помимо кликов и `ON_ENTER` / `ON_LEAVE`:

| Триггер | Когда срабатывает |
|---------|-------------------|
| `ON_JOIN` | Игрок зашёл на сервер (радиус не проверяется) |
| `ON_KILL` | Игрок убил существо рядом с NPC |
| `ON_DEATH_NEARBY` | Игрок погиб рядом с NPC |
| `ON_TIME` | Периодически, для игроков в радиусе |

`ON_TIME` сам о времени ничего не знает — нужное окно задаётся условиями.
Интервал настраивается (`settings.on-time-interval-seconds`, по умолчанию 60 с):

```
/wnpc action @ add ON_TIME MESSAGE [REALTIME:09:00-10:00][CHANCE:20]Доброе утро!
/wnpc action @ add ON_KILL MESSAGE [CHANCE:30]Хороший удар!
```

## Диалоги

Файл `dialogs/<id>.yml`, привязка — `/wnpc dialog @ set <id>`.

```yaml
start: greeting
mode: CHAT          # CHAT или GUI (окно инвентаря)
gui-size: 27        # для mode: GUI
gui-title: "&#BBDEFBТорговец"
sound: ""           # звук по умолчанию для всех узлов
typewriter: 0       # тиков на символ, 0 — выводить сразу

nodes:
  greeting:
    text: "Привет, {player}! У тебя {flag_stage} этап."
    sound: "ENTITY_VILLAGER_AMBIENT 1.0 1.2"
    typewriter: 1           # посимвольный вывод
    choices:
      1:
        label: "&#A8E6CFКупить набор — 100 монет"
        goto: bought
        conditions:                       # условия варианта
          - "PAPI:%vault_eco_balance%>=100"
          - "!FLAG:bought_kit"
        actions:                          # выполняются при выборе
          - "MONEY_TAKE:100"
          - "PLAYER_COMMAND:kit starter"
        hide-if-locked: false             # показать заблокированным
        locked-label: "&#FF8B94Не хватает монет"
        material: GOLD_INGOT              # кнопка в режиме GUI
        slot: 11                          # -1 или не указывать — авторазмещение
      2:
        label: "&#9CA3AFНазад"
        goto: back                        # вернуться на предыдущий узел

  bought:
    text: "Отличный выбор!"
    actions: ["FLAG_SET:bought_kit"]
    auto-goto: greeting                   # переход без участия игрока
    auto-delay: 60                        # через 3 секунды
```

Что нового по сравнению с прежними диалогами:

- **Условия на вариантах** — весь набор из раздела «Условия действий», а не
  только `permission`. Недоступный вариант можно скрыть (`hide-if-locked: true`,
  по умолчанию) или показать серым с подписью `locked-label`.
- **Действия на вариантах** — выполняются до перехода, поэтому следующий узел
  уже видит флаг, который вариант только что поставил.
- **`goto: back`** — возврат на предыдущий узел, история хранится в сессии.
- **`goto: close`** — завершить диалог.
- **Автопереход** `auto-goto` + `auto-delay` — реплики без участия игрока.
- **Звук узла** `sound: ИМЯ [громкость] [высота]`.
- **Печатная машинка** `typewriter: N` — текст проявляется посимвольно в
  action bar (в чате это была бы серия из десятков сообщений подряд), после
  чего выводится целиком вместе с вариантами.
- **Переменные в тексте** — `{player}` и `{flag_имя}`.
- **Режим GUI** — `mode: GUI` показывает узел окном инвентаря: реплика на
  табличке в верхней строке, варианты — кнопками. Закрытие окна завершает диалог.

## Данные игроков и флаги

Кулдауны `[CD:]`, история `[ONCE]`, скрытые NPC, личная статистика и **флаги**
хранятся персонально по игроку. Раньше это было размазано по трём местам —
внутри объектов действий, в `npcs.yml` и в отдельном `visibility.yml`.

Флаги — это фундамент для квестов: они позволяют ветвить поведение по тому,
что игрок уже сделал.

```
/wnpc action @ add RIGHT_CLICK FLAG_SET quest_started
/wnpc action @ add RIGHT_CLICK FLAG_SET stage 2
/wnpc action @ add RIGHT_CLICK FLAG_CLEAR quest_started

/wnpc action @ add RIGHT_CLICK MESSAGE [FLAG:quest_started]Ты уже взял задание.
/wnpc action @ add RIGHT_CLICK MESSAGE [!FLAG:quest_started]Возьми задание!
/wnpc action @ add RIGHT_CLICK MESSAGE [FLAG:stage=2]Второй этап пройден.
```

Значение флага доступно как `%woolynpcs_flag_<имя>%`, личный счётчик кликов —
как `%woolynpcs_myclicks_<NPC>%`.

### Где всё лежит

Настраивается в `config.yml`, секция `storage`:

| `type` | Что это |
|--------|---------|
| `yaml` | Файл на игрока в `playerdata/` — по умолчанию, ничего не требует |
| `sqlite` | Один файл `playerdata.db`; нужен драйвер `org.sqlite.JDBC` |
| `mysql` | Общая база для сети серверов; нужен драйвер MySQL |

Драйвер SQL не входит в плагин — используется только `java.sql` из JDK. Если
выбран `sqlite`/`mysql`, но драйвера нет или подключиться не вышло, плагин
напишет об этом в лог и **продолжит на `yaml`**: потерять данные игроков хуже,
чем работать на файлах.

### Обновление формата и резервные копии

`npcs.yml` помечен полем `config-version`. При первом запуске новой версии
данные из старого формата переносятся автоматически, **перед этим создаётся
резервная копия** в `backups/`. Старый `visibility.yml` переименовывается в
`visibility.yml.migrated`, чтобы перенос не повторился.

Копию можно сделать и вручную: `/wnpc backup`. Число хранимых копий задаётся
`storage.backup-count` (по умолчанию 3, старые удаляются).

## Настройка внешнего вида

Ничего не зашито в код — все окна, материалы, слоты и размеры лежат в `gui.yml`:

| Секция | Что настраивает |
|--------|-----------------|
| `editor` | Редактор NPC (`/wnpc edit`) |
| `confirm` | Окно подтверждения перед удалением |
| `picker` | Списки с листанием: выбор модели, анимации, действия |
| `dialog` | Диалог в режиме `mode: GUI` |
| `fallback-material` | Чем заменить неизвестный материал |

Меню и диалоги — обычные файлы, которые появляются в папке плагина при первом
запуске и правятся без пересборки:

```
plugins/WoolyNpcs/
├── menus/example.yml     заготовка меню
└── dialogs/example.yml   заготовка диалога
```

Любой новый `.yml` в этих папках подхватывается сам: меню — по `/wnpc menu reload`,
диалоги — по `/wnpc dialog @ reload`.

Числовые параметры поведения тоже вынесены в `config.yml`: дальность и угол выбора
NPC взглядом, анимация ходьбы, высота шага и спуска на маршруте, шаг и интервал
частиц маршрута, тайминги `TITLE`, длительность `BOSSBAR` по умолчанию, таймаут
`DISCORD_WEBHOOK`, размер корзины удалённых и глубина истории диалога.

## Поведение, о котором стоит знать

- **Смещение голограммы (`holo <имя> offset`) отсчитывается от точки крепления
  к NPC**, а не от его ног. Голограмма едет пассажиром на базовой сущности, и
  клиент всегда рисует пассажира в точке крепления — поэтому высота задаётся
  сдвигом в `Transformation`. После обновления смещение, возможно, придётся
  подобрать заново.
- **`/wnpc despawn` — постоянный**: NPC не поднимут ни расписание, ни дальность
  видимости, ни загрузка чанка, и флаг переживает перезапуск. Вернуть NPC —
  `/wnpc spawn`. Если после этого он не появился, команда скажет, что мешает.
- **Действия узла диалога выполняются один раз за сессию.** Это закрывает
  бесконечное повторение наград при хождении по вариантам «вперёд/назад».
  Сессия завершается по таймауту (`dialog-timeout-seconds`), при уходе от NPC
  (`dialog-max-distance`), при выборе `goto: close` и при выходе с сервера.
- **Кулдауны (`[CD:]`) и `[ONCE]` переживают перезаход** — раньше их можно было
  обойти релогом. `[ONCE]` привязан к идентификатору действия, поэтому удаление
  одного действия больше не сдвигает историю остальных.
- **Изменения от команд пишутся на диск пачкой** (`save-flush-interval-ticks`,
  по умолчанию раз в 5 секунд), а не при каждой команде. Создание, удаление,
  копирование, переименование и импорт сохраняются немедленно.
- **Файлы данных:** `npcs.yml` (NPC),
  `dialogs/` (диалоги), `menus/` (меню), `playerdata/` (данные игроков),
  `backups/` (копии), `exports/` (экспорт).

## Сборка и тесты

```bash
mvn clean package     # сборка вместе с тестами
mvn test              # только тесты
```

Тесты покрывают чистую логику, которую можно проверить без запущенного
сервера: расписание (включая промежуток через полночь), разбор записей
распорядка дня, разбор условий `[PAPI:]` и остальных тегов вместе с
отрицанием и группами. Эмулятор сервера намеренно не подключался — всё
остальное упирается в живой Bukkit и проверяется только на сервере.

JAR будет создан в `target/WoolyNpcs-1.0-SNAPSHOT.jar`.

Версия в `plugin.yml` подставляется из `pom.xml` при сборке (`${project.version}`),
поэтому менять её нужно только в одном месте.
